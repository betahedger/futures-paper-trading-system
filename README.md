# Futures Paper Trading System

> **API·실시간 데이터·모의주문·포지션·리스크 관리**

선물 매매전략을 단순 백테스트에서 끝내지 않고, **시장데이터 → 신호 → 주문 → 체결 → 포지션·손익 → 리스크 관리 → 로그 저장**까지 연결한 모의매매 시스템입니다.

현재 버전은 외부 계좌나 주문 권한 없이도 재현 가능하도록 `MockBroker`를 사용합니다. 주문 실행 계층을 별도 브로커 인터페이스로 분리해, 향후 외부 시장데이터·주문 인터페이스를 연결하더라도 전략·포트폴리오·리스크 관리 로직을 그대로 재사용할 수 있도록 구성했습니다.

## 시스템 흐름

```text
시장 데이터
    ↓
매매 신호 생성
    ↓
목표 포지션 계산
    ↓
리스크 한도 확인
    ↓
모의 시장가 주문
    ↓
체결 및 포지션 반영
    ↓
실현·미실현 손익 계산
    ↓
거래·상태 로그 저장
```

## 기본 전략

기본 신호는 단순 이동평균 교차를 사용합니다.

```text
단기 이동평균 > 장기 이동평균  →  목표 포지션 +1
단기 이동평균 < 장기 이동평균  →  목표 포지션 -1
```

전략 자체의 복잡성보다 **신호가 실제 주문·체결·포지션·리스크 관리로 이어지는 실행 구조**에 초점을 맞췄습니다.

## 리스크 관리

현재 구현에는 다음과 같은 기본 제한이 있습니다.

- 최대 절대 포지션 제한
- 일일 손실 한도

일일 손실 한도에 도달하면 새로운 위험을 늘리는 주문은 차단하지만, 기존 포지션을 줄이거나 청산하는 주문은 허용합니다.

## 브로커 인터페이스

전략과 주문 실행부가 직접 결합되지 않도록 공통 `Broker` 인터페이스를 사용합니다.

```text
Broker
├── MockBroker         # 현재 실행 가능한 모의체결
└── RestBrokerAdapter  # 외부 주문 인터페이스 연결용 어댑터
```

`MockBroker`는 현재 표시가격에서 시장가 주문이 즉시 체결된다고 가정합니다.

`RestBrokerAdapter`는 시세 조회·포지션 조회·주문 기능을 연결할 수 있는 인터페이스 경계를 분리해 둔 구조입니다.

## 포지션 및 손익

체결이 발생할 때 평균단가와 실현손익을 갱신하고, 현재 시장가격으로 미실현손익을 계산합니다.

- Long 청산: `(체결가 - 평균단가) × 수량 × 계약승수`
- Short 청산: `(평균단가 - 체결가) × 수량 × 계약승수`
- 반대 방향으로 포지션이 뒤집히는 경우 기존 포지션을 먼저 청산하고 잔여 수량의 평균단가를 새 체결가로 설정

## 실행 방법

```bash
pip install -r requirements.txt

# 저장소의 샘플 데이터로 모의매매 실행
python main.py

# 테스트
pytest -q
```

파라미터도 실행 시 변경할 수 있습니다.

```bash
python main.py --fast 10 --slow 30 --max-position 1 --max-daily-loss 10
```

## 실행 결과

`main.py` 실행 후 `results/`에 다음 파일이 생성됩니다.

- `paper_trading_log.csv`: 가격, 목표 포지션, 실제 포지션, 평균단가, 실현·미실현손익, 리스크 상태
- `trades.csv`: 주문번호, 종목, 매수·매도, 수량, 체결가, 체결시각

## 현재 범위와 한계

- 현재는 실제 계좌 주문이 아닌 Paper Trading 시스템입니다.
- `MockBroker`는 시장가 주문이 현재 가격에서 즉시 전량 체결된다고 가정합니다.
- 호가잔량, 부분체결, 지연, 슬리피지, 거래소별 주문 규칙은 아직 반영하지 않습니다.
- 일일 손실 한도는 시뮬레이션 내부 손익을 기준으로 계산합니다.
- 현재 버전은 외부 실거래 API의 인증·실시간 시세·주문 엔드포인트를 직접 연결하지 않습니다.

- 전략과 실행 시스템을 분리한 이벤트 기반 구조로 확장
